# Student import diagnostics

## 2026-11-09 — resolution

Root cause established: files generated by external/AI tools may use prefixed SpreadsheetML elements (`<x:workbook>`, `<x:worksheet>`, and `<x:styleSheet>`) and leading UTF-8 BOMs. ExcelJS 4 parses tags by literal element name, leaving the workbook model undefined and throwing `TypeError: Cannot read properties of undefined (reading 'sheets')` during `workbook.xlsx.load()`.

Solution:
1. `normalizeSpreadsheetXmlNamespaces` uses `@xmldom/xmldom` and JSZip to remove XML BOMs and normalize prefixed SpreadsheetML elements while preserving attributes, text, and other OpenXML namespaces.
2. Unexpected ExcelJS load failures now become an `InputError` with a safe HTTP 400 message rather than a generic 500.
3. ExcelJS, JSZip, and xmldom are loaded as native Node packages through `serverExternalPackages`.
4. Temporary diagnostic logging was removed.
